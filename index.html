Multi-Domain Constraint-Based
SR-MPLS Traffic Engineering

Exploring how a centralized SDN/PCE controller can perform constraint-based traffic engineering across multiple independent SR-MPLS domains interconnected by BGP-LU.

Test Objective

This lab is designed to study how OpenDaylight can build a global traffic-engineering view and perform constraint-based path computation across multiple independent SR-MPLS domains. The objective is not to collapse the regions into one IGP domain, but to preserve regional autonomy while enabling end-to-end traffic engineering.

Regional Architecture

The environment contains four independent regional SR-MPLS domains: Australia, Singapore, Japan and Hong Kong. Each region contains Provider Edge (PE) routers and Provider Border Routers (PBRs), with its own IS-IS/SR-MPLS control plane.

Inter-Domain WAN

The regions are interconnected through BGP Label Unicast (BGP-LU) links between the PBRs. The validated lab contains 10 physical WAN links represented as 20 directional topology edges. Australia and Japan have no direct WAN connection.

Global Traffic Engineering

BGP-LS provides topology and SR information to OpenDaylight. The controller builds a global Traffic Engineering Database (TED), allowing SPF, CSPF and SAMCRA to evaluate an end-to-end path across regional boundaries.

Path Programming

The selected global path is translated into domain-specific SR-MPLS forwarding instructions plus the required BGP-LU transition. PCEP is then used to program the resulting LSP on the ingress router.

End-to-End Control Workflow

BGP-LS feeds regional topology and SR information into the global TED. WAN telemetry enriches the inter-domain links with engineering metrics. CSPF or SAMCRA computes the constrained end-to-end path, which is then decomposed into native per-domain SR segments and BGP-LU transitions. OpenDaylight finally uses PCEP to program the resulting LSP on the ingress PE.

BGP-LS → Global TED → Constraints → CSPF / SAMCRA → Path Decomposition → SR-MPLS + BGP-LU → PCEP

Key Architectural Point

Topology visibility and forwarding reachability are separate problems. A controller can understand the global topology through BGP-LS, while independent IGP domains still require an inter-domain forwarding mechanism such as BGP-LU. The experiment demonstrates how these pieces can be combined into a single constraint-based TE workflow.

Actual EVE-NG Lab Topology

The complete EVE-NG implementation of the four independent regional SR-MPLS domains. Each region maintains its own IS-IS / SR-MPLS control plane, while Provider Border Routers (PBRs) provide the physical inter-domain connectivity used by the BGP-LU multi-domain traffic-engineering test.
